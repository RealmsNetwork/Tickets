# Contributing

1. Open an issue describing the user-visible behavior or bug.
2. Keep changes focused and add regression tests for new logic.
3. Never submit proprietary source copied from another project, real tokens,
   server IDs that should remain private, or user ticket transcripts.
4. Run `npm test` and `npm run check` before opening a pull request.
5. Prefer additive migrations and document new configuration keys in
   `config/settings.example.json` and the README.
